Normal Rails pages (like app/views/*.html.erb) require the whole Rails application to be loaded and working — the router, the controllers, the database connection, etc. But some errors happen precisely because part of that machinery is broken or was never reached (e.g. malformed request data, or — for the related 500.html file — the app crashing outright). If Rails tried to render a "fancy" error page through the normal view-rendering pipeline in those situations, rendering the error page could ALSO fail, leaving the visitor with nothing useful at all. Web servers (like Puma, or a reverse proxy in front of it) can hand back a file from the public/ directory directly, without booting any Ruby code, so this page keeps working even in a worst-case scenario.
